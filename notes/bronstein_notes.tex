% --- Comment 2 (p.31): equivariance is rich + compositional; non-linearities
% CKJ notes: (a) the non-linearity is not GNN-specific, but worth a brief
% mention that -- as in any NN -- non-linearities matter; (b) explicitly state
% that COMPOSITIONS of equivariant maps stay equivariant (even through
% non-linearities), and that equivariances are VERY RICH.
% [QUOTE] (anchor, trimmed; Bronstein et al. sec 3.5): "the family of linear
%   invariants is not a very rich object, [whereas] the family of linear
%   equivariants provides a much more powerful tool, since it enables the
%   construction of rich and stable features by composition with appropriate
%   non-linear maps ... if B is G-equivariant ... and sigma is an arbitrary
%   (non-linear) map then ... U := (sigma o B) ... is also G-equivariant".
% [REWRITE]: Linear invariants are a thin toolbox -- there simply are not many
%   of them. Linear equivariants are far richer, and (crucially) COMPOSITIONAL:
%   stack equivariant maps and interleave them with pointwise non-linearities,
%   and the result is still equivariant. For a GNN this is the permutation
%   case -- apply a non-linearity to each node's features and THEN relabel the
%   nodes, or relabel and then apply: the two agree, so equivariance survives
%   every layer. This is exactly why deep equivariant networks are easy to
%   assemble by stacking. The non-linearity itself is nothing GNN-specific:
%   as in any neural network it is what keeps a deep stack from collapsing into
%   a single linear map -- worth one sentence, no more.
% [CAVEAT to keep in mind, not from the comment]: pointwise non-linearities
%   preserve equivariance when the group acts on the DOMAIN (permutations,
%   shifts). When the group acts on feature CHANNELS (e.g. SO(3) on vector/
%   tensor features), naive element-wise non-linearities BREAK equivariance --
%   which is why steerable nets (TFN/e3nn) act non-linearly only on invariant
%   norms. Pairs with the appendix and the "implementing other symmetries" note.

\begin{svgraybox}
\textbf{The Geometric Deep Learning blueprint.}
Almost every successful deep architecture is one recipe applied to a different
domain and symmetry. Fix a domain $\Omega$ with symmetry group $G$ and assemble
four kinds of block:
\begin{itemize}
  \item \textbf{Equivariant layer} $B$ -- mixes features in step with $G$
        (message passing on a graph, convolution on a grid):
        $B(g.x)=g.B(x)$.
  \item \textbf{Non-linearity} $\sigma$ -- applied pointwise, as in any network.
  \item \textbf{Local pooling (coarsening)} $P$ -- optionally shrinks the domain
        ($\Omega'\subseteq\Omega$) while preserving the symmetry.
  \item \textbf{Global pooling} $A$ -- reads out a $G$-\emph{invariant} answer:
        $A(g.x)=A(x)$.
\end{itemize}
Stacking equivariant blocks (with non-linearities and optional coarsening) and
finishing with a global invariant readout gives
\[
  f \;=\; A \circ \sigma_J \circ B_J \circ P_{J-1}\circ\cdots\circ
          P_1 \circ \sigma_1 \circ B_1 .
\]
CNNs, GNNs, Transformers, and Deep Sets are all this blueprint -- they differ
only in the choice of domain $\Omega$, symmetry group $G$, and how each block is
realized. (After \citealp{Bronstein2021_geometricDL_book}.)
\end{svgraybox}
